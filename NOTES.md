# Field notes

Dated observations with receipts — the evidence behind the grid in `SKILL.md`.
Most come from the live multi-agent experiment on
[open-learning-exchange/myplanet PR #15436](https://github.com/open-learning-exchange/myplanet/pull/15436)
(2026-08-07/08), where each agent also fact-checked its own row, plus the
follow-up on [PR #15499](https://github.com/open-learning-exchange/myplanet/pull/15499)
(2026-08-09). Append here; retest and retire what goes stale. (Adopting the
spellbook in another repo? Take the grid, the laws, and the vendor links from
`SKILL.md` — then grow your own notes.)

- **Connecting-test baseline** — 2026-08-21: the connecting test's first live run (on this repo's PR #2, probes posted 09:41–09:42 UTC) passed five-for-five inside the window: CodeRabbit's `help` command list in ~14 s, Codex's 👀 in under a minute (a *reaction*, which emits no webhook event — poll the probe comment's reactions, don't wait on the timeline), OpenHands "I'm on it!" in ~23 s with the session's leashed answer at ~70 s, Copilot "connected, no push" in ~41 s, Devin "Starting Devin Review" in ~6 s. Every probe carried trailing attribution text and every trigger tolerated it, `/devin review` included.
- **Connection silence** — 2026-08-21: five agents summoned on this repo's [PR #2](https://github.com/dogi/agents-summoning/pull/2) before their apps were activated for the owner's personal repos — CodeRabbit, Codex, Devin, and OpenHands returned no ack, no error, nothing; all answered within minutes of activation. An org-level install does not cover personal repos, and not-connected presents as perfect silence — the first diagnosis under Law 5, and the experiment `references/connecting.md` was born from.
- **Summoner identity** — 2026-08-21: summons cast through Claude Code's GitHub tooling post under the connecting user's own account, not a bot — which is exactly what satisfies Copilot's write-access-users-only mention rule.
- **Devin triggers** — 2026-08-21: the review trigger is form-picky — `@devin review` with trailing text went silent three times on PR #2, while `/devin review` fired within seconds three times, trailing text and all. The session ask (`@devin <ask>`) worked on the PR (session link in 3 s) and delivered three line-anchored one-click suggestions, including relaying the web-gated Devin Review findings. On an issue page both the `@devin` and `/devin` forms went silent — Devin's surfaces are the PR only.
- **Codex** — 2026-08-21: two lanes with different auth. `@codex review` works via the repo-level integration and delivered three valid P2s on consecutive runs (`--checkout` on submodule bumps, Copilot fork-PR scoping, fresh-clone `--init`) plus one plausible-but-refuted P1 (plugin symlinks dangling in the cache — refuted by the plugin reference: marketplace installs dereference within-marketplace symlink targets at copy time; verify a P1 against vendor docs before restructuring). The free-form `@codex <ask>` bounced on the PR with "create a Codex account and connect to github" yet answered on the issue page with a task link — the chat lane depends on account connection and routing, per surface.
- **Copilot** — 2026-08-21: PR mentions answered in ~2 min with valid findings, every leash honored, and it first-party-corrected this repo's claim about itself (skills are discovered directly from `.github/skills`, `.claude/skills`, and `.agents/skills` — verified against the docs). Asked to demonstrate suggestion blocks, it wrote the ` ```suggestion ` syntax inside a plain issue comment — unanchored, so no one-click apply button; mention-asks cannot create review comments. Issue-page mentions go silent; assignment remains its issue path.
- **CodeRabbit** — 2026-08-21: answers mentions on issue pages too. Live-confirmed its grid mechanics in one afternoon: "Already reviewed" against an unchanged head, forced single review while auto-paused, auto-pause under a commit influx, "✅ Addressed in commit X" self-marks. Three reasoned declines produced three graceful withdrawals, each storing a learning of increasing generality (thread-specific → file convention → repo-wide placeholder rule).
- **OpenHands** — 2026-08-21: honored "comment only" on every one of five-plus summons, once explicitly narrating that the leash overrode its default branch-and-PR workflow; posted a proper line-anchored one-click suggestion on request; answers issue-page mentions. One session errored loudly at start ("Uh oh! There was an unexpected error starting the job") — an outage announces itself, unlike not-connected silence — and an identical retry worked. Its review comments post under the token owner's account with an AI-disclosure line — the timeline rule again.
- **Jules** — 2026-08-21: mention-deaf on both surfaces of this repo — leashed asks on the PR and the issue, plus a bare "are you there?", all silent. The `jules` label on an issue remains its only summon, and the label means "implement this issue".
- **Reviewer dialectic** — 2026-08-21: Devin flagged a real contradiction (version bump vs. main-tip tracking) but its suggested fix inverted the truth; CodeRabbit's docs-cited follow-up corrected the correction (a present `version` field gates existing-install updates). Apply a reviewer's *finding*; verify its *fix*.
- **Devin Review** — 2026-08-21: on this repo's PR #2 the web-UI gate holds only for humans — a Devin *session* can pull the findings back out (`get_review_findings`) and relay them, so ask a session rather than screenshotting the UI. They are also fallible: the one "new potential issue" reported here flagged `devin_review_ignored_file_changes.md` as a stray tool artifact committed to the repo root, and that path exists in no commit on the branch (`git log --all -- <path>` is empty) — Devin Review can surface its own scratch artifacts as if they were repo files. Verify a finding against the tree before acting on it.
- **Devin** — 2026-08-09: on [PR #15499](https://github.com/open-learning-exchange/myplanet/pull/15499), two verbose review asks (`@devin please review — comment only, focus on…`) got **no response at all**; the bare literal `@devin review` answered within ~1 min — via **Devin Review**, its automated reviewer, not a session ("No Issues Found", with "3 additional findings" visible only at app.devin.ai). Treat `@devin review` as a fixed command: leashes and focus instructions in the trigger comment suppress it rather than steer it. Later the same day, four consecutive mentions (`review` ×2, `?` ×2) produced only two "Failed to start a Devin session. Please try again." replies — an outage presents as silence or that error; retry later instead of rephrasing.
- **All mention-summoned agents** — 2026-08-09: ⚠️ **backticks don't defuse a mention.** Writing `` `@openhands prepping` `` inside a code span in an ordinary status comment on PR #15499 spawned a real (unleashed!) OpenHands session. GitHub notifies on the handle regardless of code formatting. When *talking about* an agent, drop the `@` (write "openhands prepping") — only use the live handle when you mean to summon.
- **OpenHands** — 2026-08-09: honored "comment only — do not push" on **three consecutive summons** on PR #15499 (softening the 2026-08-07 leash-break note — mixed, not hopeless), and was the only reviewer to live-test the target environment: it caught the same skill silently dropped by discovery **twice for different reasons** — first a too-generic `name: title`, then (after the rename) invalid YAML from an unquoted `description:` containing `scope:`. Ask it to *verify by running*, not just review — that's its edge. Still double-posts under the mentioning user's account and the bot.

- **Jules identity** — 2026-08-21: in this repo's PR #4 the sole commit `caf13cf` wore **the requesting user's git identity for both author and committer** (`dogi <13684059+dogi@users.noreply.github.com>`), and PR #4's `user` field reads `dogi` too — the Jules bot handle `google-labs-jules[bot]` did not appear as PR author, committer, or co-author anywhere. - **`@jules` ≠ the Jules bot** — 2026-08-21: a bare `@jules` in an issue body would have notified an unrelated **human GitHub user** `jules` (type `User`, `gh api users/jules` resolves), not the Jules agent — whose bot identity is `google-labs-jules[bot]` and whose issue-summon is the `jules` label, not a mention (mentions stay dead on issues per the 2026-08-21 mention-deaf note). The body was therefore written without the `@` ("jules try to load skill …") to avoid pinging the human; Law 3 again, and the rare case where the live handle isn't even `@<lowercase-name>`.
