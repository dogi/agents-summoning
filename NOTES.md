- **The connection probe IS the summon (OpenHands self-summon)** — 2026-08-21: ⚠️ meta-lesson. Posting the OpenHands connection probe `@openhands are you connected? Comment only — do not push anything.` on PR #4 and on issue #3 did not merely *ping* OpenHands to confirm connectivity — it **summoned two real, separate OpenHands sessions** (distinct conversation IDs: `ea1b53f6…` on the PR, `f00c88ba…` on the issue), one per surface, because *any* OpenHands mention reads as "fix what's open" and spawns a fresh session (Law 4). The summoner summoned itself. This is the trap Law 3/4 warn about, made concrete: **a connection-test probe of a Doer is itself an unleashing** — the leash held here (neither session pushed; the PR's branch head stayed `fc2d9bf` through the probe window, no new branches), but per Law 2 a leash is a request, not a restraint. OpenHands honored it on **both** surfaces and even narrated the override on the issue ("I did not create a branch, push code, or open a PR, even though the default workflow suggests doing so. The latest request takes precedence"). More evidence softening the 2026-08-07 leash-break — OpenHands has now honored no-push on 7+ consecutive summons (the five noted above, plus these two). Also refined the grid's "double-posts": here it **triple-posted** per surface — (1) `openhands-ai[bot]` "I'm on it!" ack ~20 s, (2) a `dogi`-authored answer ~26 s later, (3) a `openhands-ai[bot]` summary later still (38 s after the answer on the PR, 10 s on the issue) — i.e. posts under both identities, with a bot-authored summary as a third. The two sessions did not race only because they landed on **different surfaces** (PR vs issue); two `@openhands` mentions on the *same* PR/issue in quick succession would race (Law 4). Practical upshot: the connecting test's doer probes are not free of side effects — they spin up real doer sessions — so run them on a branch that can absorb a surprise commit and expect a session per doer probe, not just a comment back. (CodeRabbit/Devin/Codex probes are Reviewers or review-commands and did not spawn actor sessions; Copilot's probe also summoned it, but it answered without pushing or branching.)

An org-level install does not cover personal repos, and not-connected presents as perfect silence — the first diagnosis under Law 5, and the experiment `references/connecting.md` was born from.

- **Jules greeting = first-party mechanics** — 2026-08-21: the `google-labs-jules[bot]` "👋 Jules, reporting for duty!" comment it posts on its own PR states the contract in its own words: it adds 👀 to each comment it has read, it pushes a commit with requested changes (with a delay between the two steps), **Reactive Mode** (global setting → Pull Request section at [jules.google.com/settings](https://jules.google.com/settings)) narrows it to comments that `@jules` it, and "for security, I will only act on instructions from the user who triggered this task" — a first-party statement of the same summoner-scoped trust model Copilot enforces via write access. - **Auditing a repo you can't API into** — 2026-08-22: when a session has git-read but no GitHub API for a repo, `patch-diff.githubusercontent.com/raw/<owner>/<repo>/pull/<n>.patch` still serves the full commit stream — author, committer, dates and `Co-authored-by:` trailers — which is exactly what an agent-attribution audit needs. `github.com/<owner>/<repo>/pull/<n>.patch` and `api.github.com` were both refused in the same session; the patch host was not. Page-summarizing fetchers are not a substitute — one invented a bot handle ("google-labs-julius[bot]") on this very PR. Receipts from the patch stream, never from a summary.
- **`@jules` ≠ the Jules bot** — 2026-08-21: a bare `@jules` in an issue body would have notified an unrelated **human GitHub user** `jules` (type `User`, `gh api users/jules` resolves), not the Jules agent — whose bot identity is `google-labs-jules[bot]` and whose issue-summon is the `jules` label, not a mention (mentions stay dead on issues per the 2026-08-21 mention-deaf note). The body was therefore written without the `@` ("jules try to load skill …") to avoid pinging the human; Law 3 again, and the rare case where the live handle isn't even `@<lowercase-name>`.
